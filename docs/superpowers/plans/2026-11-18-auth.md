# Auth & Biometric Security Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace hardcoded env-var credentials with a login flow, encrypted SecureStore, biometric re-lock, and logout.

**Architecture:** An `AuthProvider` wraps the app and owns a four-state machine (`loading → unauthenticated → needs_biometric → authenticated`). The root layout renders `LoginScreen`, `LockScreen`, or the existing `Stack` based on that state. `api.ts` replaces static constants with mutable module vars set by the auth layer.

**Tech Stack:** Expo SDK 58, `expo-secure-store`, `expo-local-authentication`, React Context, TypeScript strict

**Spec:** `docs/superpowers/specs/2026-11-18-auth-design.md`

## Global Constraints

- Expo SDK 58 — use `expo install` for all new packages
- TypeScript strict; no `any` in new code
- Visual style: `#228be6` blue, `#f4f6f8` background, `#ffffff` cards, border-radius 14
- German UI copy throughout (spec's exact strings: "TameTheWild entsperren", "PIN verwenden", "Abbrechen", "Entsperren", "Abmelden")
- No "skip biometrics" path — the only bypass is "Abmelden"
- When `isEnrolledAsync() === false`: show LockScreen with message only and "Abmelden", no "Entsperren" button (avoids infinite loop)

## Review Focus

- **Login with trailing `/api/` in URL** — `normalizeBaseUrl` must strip `/api/` so POST goes to `{base}/api/token/` not `{base}/api/api/token/`; covered by Task 1 Step 1.
- **401 from token endpoint** — `fetchToken` must throw a typed error so LoginScreen shows the correct German inline message, not an unhandled rejection; covered by Task 1 Step 1.
- **AppState re-lock fires while already in `needs_biometric`** — listener must only transition `authenticated → needs_biometric`, never re-enter from `needs_biometric`; covered by Task 3 Step 1.
- **No enrolled biometrics on emulator** — `biometricAvailable: false` in context must hide "Entsperren" and show the info message on LockScreen; covered by Task 3 Step 1.
- **`getBaseUrl()` returns `''` before login** — API calls made before `setApiCredentials` are called must throw, not silently hit wrong URLs; existing `fetchAll` already throws on non-OK HTTP, which is sufficient — no extra guard needed.

- Response 400/401 → `throw new Error('invalid_credentials')`
- Network error (fetch throws) → `throw new Error('network_error')`

### Task 3: `src/context/AuthContext.tsx`

**Files:**
- Create: `src/context/AuthContext.tsx`

**Interfaces:**
- Consumes:
  - `loadCredentials, clearCredentials, checkBiometricAvailable, authenticateBiometric` from Task 1
  - `setApiCredentials` from Task 2
- Produces:
  - `export type AuthState = 'loading' | 'unauthenticated' | 'needs_biometric' | 'authenticated'`
  - `export interface AuthContextValue { authState: AuthState; biometricAvailable: boolean; login(url: string, token: string): void; logout(): Promise<void>; unlockBiometric(): Promise<void>; }`
  - `export function AuthProvider({ children }: { children: React.ReactNode }): JSX.Element`
  - `export function useAuth(): AuthContextValue`

- [ ] **Step 1: Implement `AuthContext.tsx`**

`AuthProvider` behavior:

**On mount:**
1. `loadCredentials()` — if null: `setAuthState('unauthenticated')`; if found: `setApiCredentials(url, token)`, `available = await checkBiometricAvailable()`, `setBiometricAvailable(available)`, `setAuthState('needs_biometric')`

**AppState listener** (registered once on mount, cleaned up on unmount):
```ts
AppState.addEventListener('change', next => {
    if (next === 'active' && authStateRef.current === 'authenticated') {
        setAuthState('needs_biometric');
    }
});
```
Use a `ref` to read `authState` inside the listener without stale closure. Only transitions `authenticated → needs_biometric`.

**`login(url, token)`**: `setApiCredentials(url, token)`, `setAuthState('needs_biometric')`

**`logout()`**: `clearCredentials()`, `setApiCredentials('', '')`, `setAuthState('unauthenticated')`

**`unlockBiometric()`**: `success = await authenticateBiometric()`; if true: `setAuthState('authenticated')`

### Task 4: `components/LoginScreen.tsx` and `components/LockScreen.tsx`

- Create: `components/LockScreen.tsx`

**Interfaces:**
- Consumes: `useAuth()` from Task 3; `fetchToken, normalizeBaseUrl` from Task 1
- Produces: both components (no exported types needed)

- [ ] **Step 1: Implement `components/LoginScreen.tsx`**

Three `TextInput` fields: **Server-URL** (`keyboardType="url"`), **Benutzername**, **Passwort** (`secureTextEntry`).
One primary button: **Anmelden** (disabled while `submitting`).
One `errorMessage: string | null` state shown inline below the button in `#fa5252`.

On press:
1. `fetchToken(url, username, password)`
2. success → `auth.login(normalizeBaseUrl(url), token)`
3. `Error('invalid_credentials')` → `setError('Benutzername oder Passwort falsch.')`
4. `Error('network_error')` → `setError('Server nicht erreichbar. URL prüfen.')`
5. any other error → `setError('Anmeldung fehlgeschlagen.')`

Style: full-screen `#f4f6f8` background, centered white card, same border-radius/color system as rest of app.

- [ ] **Step 2: Implement `components/LockScreen.tsx`**

Reads `biometricAvailable` from `useAuth()`.
Auto-triggers `unlockBiometric()` once on mount via `useEffect(... , [])` — only when `biometricAvailable === true`.

When `biometricAvailable === true`: shows **Entsperren** button (primary, `#228be6`) + **Abmelden** button (destructive, `#fa5252`).
When `biometricAvailable === false`: shows message `'Keine Bildschirmsperre eingerichtet. Bitte richte eine Geräte-PIN oder Biometrie ein.'` + only **Abmelden** button.
